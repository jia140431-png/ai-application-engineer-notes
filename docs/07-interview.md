# 面试自测与参考答案

[返回目录](../README.md) · 来源：补充题；第 9 题与原对话的 RAG 复盘相关。

## 使用方法

先闭卷口述，再看答案。每题按概念正确、说明取舍、覆盖失败场景、给出验证方法四项各 0—2 分自评。这只是定位复习缺口，不是岗位能力评级。不要求编写项目。

## 题目

1. 用一分钟解释大模型怎样生成回答，并解释为什么会出错。
2. RAG、Prompt 与微调分别改变什么？
3. 用户要求实时库存，为什么不能只查向量库？
4. 流式工具参数到一半，能开始执行业务动作吗？
5. 低温度和结构化输出能保证什么，不能保证什么？
6. 如何判断检索失败是切分、向量模型还是排序问题？
7. RAG 检索指标提升，答案正确率下降，怎么解释？
8. Agent 与传统工作流如何配合？
9. 用户反馈 RAG 经常答非所问，怎样定位？
10. 工具创建工单超时，是否重试？
11. 审批三小时后恢复，怎样避免重复操作或使用过期批准？
12. 有 Checkpoint 为什么仍无法自然获得 Exactly-once？
13. 什么时候值得使用多 Agent？
14. Spring AI、图编排、MCP、A2A 各负责什么？
15. 如何判断自己已经理解，而不是只会复述名词？

## 参考答案与追问

### 1. 生成与错误

将输入分词、计算上下文表示，逐步预测下一个 Token。概率上合理的延续不等于事实正确。缺知识、错误前提和证据冲突都会导致错误。追问：能否区分模型权重知识和当前上下文证据？

### 2. 三种改进方式

Prompt 改本次指令与输入组织；RAG 获取外部证据；微调修改参数中的行为模式。可组合，不是简单互斥。追问：每天更新制度选哪条路径，如何保持版本？

### 3. 实时业务事实

向量库可能只存历史快照且缺业务约束。实时库存查询应走带身份与权限校验的权威接口；回答附带查询时间。追问：查询之后到下单之前库存变了怎么办？由业务预占或事务规则处理。

### 4. 增量参数

先按协议收齐调用，再解析、校验和授权。半截 JSON 可能被后续修改，也可能最终截断。追问：断流后如何防止误执行或重复执行？

### 5. 格式与事实

低温度通常减少随机性；结构化约束提高格式可控性；两者不保证事实、权限和业务条件正确。追问：举出一个 JSON 完全合法但必须拒绝执行的动作。

### 6. 逐层证据

先确认源文档与解析片段有正确证据，再看候选、排名和最终上下文；固定语料与查询，逐个替换切分或模型做实验。不能仅看最终答案猜组件。追问：换 Embedding 为什么通常要重建索引？

### 7. 指标与目标

可能召回更多重复或不适用资料、冲突文档挤占预算，或指标只测宽泛相关性。把检索标注与答案证据需求对齐，并查看每类样本。追问：是否有错误资料被模型忠实复述？

### 8. 流程与模型

确定审批和权限由业务规则控制，模型处理开放文本、提取意图与动态查询。给 Agent 设置受限工具与退出条件。追问：为什么让模型决定审批权限不可靠？

### 9. RAG 诊断

确认影响范围；比较代码、配置、知识、索引和模型变化；固定条件跑回归；逐阶段找证据丢失点；用最小正确证据 Prompt 隔离；修复后回归和观察。详见[案例](08-rag-diagnosis.md)。

### 10. 超时与幂等

先区分明确失败与结果未知。以原 operationId 查询下游，确认幂等契约后有界重试。换新操作 ID 会破坏去重。追问：下游不支持幂等怎么设计？可建立业务唯一约束、操作台账或对账人工处置，不能仅靠模型承诺。

### 11. 审批恢复

审批绑定操作及参数版本；恢复后查可信记录，核验身份、有效期、取消状态和当前业务条件；执行依赖下游幂等。追问：参数改变是否需要重新批准？通常需要按变更策略重新确认。

### 12. 两个提交边界

下游业务成功与保存 Checkpoint 是不同提交，二者之间可能故障。恢复意味着可能重放。需要业务幂等、结果查询和对账，而不是宣称框架提供跨系统 Exactly-once。

### 13. 多 Agent

专业分工、权限隔离、独立生命周期或可测的并行收益成立时再引入。比较质量、成本、延迟和失败率。追问：能否先用单 Agent 加工具实现同样需求？

### 14. 分层

Spring AI 提供 AI 能力集成，图编排负责状态流转与执行，MCP 连接外部能力，A2A 处理 Agent 间互操作。业务系统继续维护授权、审批和业务事实。追问：哪个组件保证付款不重复？应落到业务执行契约。

### 15. 理解验证

能画链路，能说每步输入输出，能设计反例、定位失败和说明验证方法。面试中将“学过”“纸上设计”“实现过”“线上验证过”分开表达。不能把这份笔记当作项目履历。
